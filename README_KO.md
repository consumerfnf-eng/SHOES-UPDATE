## 2026-10-07 기준 변경

신규 수집은 공식 **New / New Arrivals / 상품별 NEW 표시**를 근거로 합니다. 출시일이 공개되지 않아도 상품·품목·공식 사진이 확인되면 게시할 수 있습니다. 단순 최신순 정렬, 검색 노출일, 발견일을 신상품 표시나 출시일로 바꾸어 사용하지 않습니다. 기존에 검증해 게시한 기록은 게시 기간 동안 유지합니다.

사이트 게시 기간은 **최초 게시일의 한국시간 날짜부터 달력상 3개월**입니다. 예를 들어 10월 7일 게시한 상품은 1월 7일에 숨깁니다. `data/publication-history.json`에 최초 게시일을 고정하며 재수집으로 연장하지 않습니다. 기존 최초 게시일은 Git의 공개 카탈로그 이력에서 복원했습니다. 사진 검토 대기나 미게시 수집 후보에는 게시 시계를 시작하지 않습니다.

일요일 08:00 KST 수집과 매일 07:15 KST 만료·이관은 GitHub Actions에서 실행합니다. 연결된 파일은 `config/archive-sheets.json`의 기존 Google Sheets입니다. 출시일 미공개 상품은 출시일 셀을 비워 두고 최초 게시일·New 근거·이관 예정일을 새 이미지 셀의 메모에 보존합니다. 기존 값은 덮어쓰지 않으며 실패하거나 결과가 불확실한 전송은 대기열과 암호화 기록으로 보존합니다. 브라우저도 만료 날짜에 즉시 숨깁니다. 서버 예약 지연 시 시트 전송은 다음 유지보수 실행에서 처리됩니다.

`scripts/new-arrivals.mjs`는 전체 운영 브랜드의 공식 목록과 발견된 New 경로·다음 페이지를 읽고 상품 상세를 확인합니다. 도메인별 요청 간격과 일시 오류 재시도, 설정된 국가별 대체 경로를 유지합니다. 한 브랜드당 목록 페이지 한도는 기본 16이며 한도/파싱/접근 오류는 coverage에 남깁니다. 응답 성공이나 일부 상품 검증을 전상품 확보로 표시하지 않습니다. 읽을 수 있는 상품 페이지라도 이미지가 빠졌으면 공식 HTML의 지연 로딩 갤러리를 한 번 더 확인합니다. 한 지역의 페이지가 다른 국가의 첫 조회를 막지 않도록 지역별 시작 페이지를 먼저 처리합니다. 사진은 기존 개별 검토와 확인된 SKU별 측면 사진 슬롯을 통과해야 게시됩니다.

스니커즈·스니커즈 밑창의 혼합형·발레리나/메리제인/뮬 스니커즈·플랫 젤리·캐주얼 플랫폼을 포함합니다. 구두·슬링백·힐·로퍼는 모든 신규 근거보다 먼저 제외합니다. 이하 날짜별 설명 중 출시일부터 3개월 규칙은 과거 운영 이력입니다.

이번 검증본은 기존 78개에서 **231개 상품 기록 / 122개 모델 카드**로 늘었습니다. 153개 색상 기록을 추가했고, 총 156개에는 공식 New 표시 근거가 있습니다. 필수 25개를 포함한 60개 브랜드를 조회했지만 전상품 수집 완료는 아닙니다. 루이비통의 일부 사진, 셀린느·생로랑·에르메스의 New 대상 범위 등은 추가 확인이 필요합니다. 필수 브랜드를 조용히 수집 대상에서 빼거나 일반 상시 판매품을 New로 바꾸지 않습니다. `sourceStatus.coverage`, `data/curation-review.json`에서 미확인 상태를 추적합니다.

검증: Node 자동 검사 198개, Python 3개, 실제 Edge에서 122개 카드·PANE 62색상/6개 카드 묶음·상세 컬러 전환·모바일 화면·CSV/XLSX 다운로드. 원본 공식 사진 229개는 파일 해시로 캐시를 확인했습니다.

`SNS 인기 신상` 탭은 기존 검증 지표 필터와 연결했습니다. 공식 신상품 중 모델/품번이 연결된 공개 검색량·해시태그 게시물 수, 측정 기간·국가·원문을 확인한 상품만 노출합니다. 현재 충족하는 상품은 0개이며 일반 신상품을 임의로 인기 상품으로 올리지 않습니다. [TikTok 공식 Trends 안내](https://ads.tiktok.com/resources/help/article/how-to-use-trends?redirected=2)의 공개 해시태그 동향을 발견 출처로 삼되, 포괄적 `sneakers` 해시태그를 특정 제품 인기 근거로 사용하지 않습니다. 계정 접근이나 공개 수치 부재가 있으면 미확인으로 남깁니다.

기존 출시일 기준 이관 대기 3건도 최초 게시 이력(2026-09-29)을 적용해 2026-12-29까지 `archive-queue.deferred`로 보존합니다. 과거 전송 영수증에 미대조 상태가 있으면 무작정 재전송하지 않습니다. 새 규칙에서 아직 3개월이 지나지 않은 상품은 이관 대상으로 보내지 않습니다.

## 데이터 위치

- `collector/runtime.html`: 기존 수집기. 공개 디렉터리 밖에 보존했습니다.
- `data/catalog-source.json`: 원본 2,250개와 이후 수집 기록. 불명확한 기록을 삭제하지 않습니다.
- `data/release-evidence.json`: 사람이 직접 확인한 출시일/상품 근거. 기존 기록은 ID 또는 정확한 SKU로 보완합니다.
- `data/curation-review.json`: 사이트 미노출 검토 목록과 대기 사유.
- `data/archive-queue.json`: 실제 게시일부터 3개월이 지난 상품과 이전에 전송 대기 중이던 기록.
- `data/publication-history.json`: 최초 공개 시각과 복원 근거. 재수집/유지보수에서도 보존합니다.
- `public/data/catalog.json`: 공개 완성본. 브라우저는 이 파일만 읽습니다.
- `config/brand-policy.json`: 승인된 필수 25개, 우선 수집 36개, 모델별 검토, 제외/보류 브랜드.
- `config/signal-sources.json`: 공개 매체/뉴스레터/검토된 SNS 계정/확인 가능한 랭킹 설정.

`collector/`, `data/`, `config/`의 커밋된 파일은 사이트에서 제공하지 않지만 공개 GitHub 저장소에서는 열람할 수 있습니다. 사이트 미노출은 비공개를 의미하지 않습니다. 이 위치에 인증 정보나 Google Sheets 원본 스냅샷·메타데이터를 평문으로 저장하지 않습니다. 시트 백업과 처리 영수증은 아래의 별도 암호화 저장 방식을 사용합니다.

## 선별 원칙

브랜드 → 실제 품목 → MLB/DISCOVERY 참고 구조 → 공식 New 표시 또는 기존 출시 근거 → 상품/이미지 확인을 모두 통과해야 공개됩니다. 수집일, 검색 노출일, NEW ARRIVAL 표기를 출시일로 바꾸어 기록하지 않습니다.

- 신규 수집: 현재 공식 New / New Arrivals 또는 해당 상품의 NEW 표시를 확인합니다. 실제 출시일은 미공개일 수 있습니다.
- 게시 기간: 최초 게시일의 KST 날짜부터 달력상 3개월 미만. 재수집해도 최초 게시일을 바꾸지 않습니다.
- 발매 예정: 내부 보존하며 현재 공개 상품 목록에서는 제외합니다. 공식 지역 발매일은 국가를 기록합니다.
- 구두/로퍼/하이힐/방한화/특정 경기 전용화는 제외합니다. 혼합형은 모델별 승인과 근거를 요구합니다.
- 공식 달력 어댑터: Nike SNKRS의 상품 ID에 연결된 launch entry, ASICS의 상품별 launch tile, Salomon의 상품별 upcoming calendar, New Balance의 상품별 명시적 연·월·일 출시 달력. 재입고·연도 없는 날짜는 새 출시로 사용하지 않습니다. 일반 PDP는 정확한 모델/SKU에 결합된 출시 문장만 인정합니다.
- 과거 출시일은 정확한 모델·품번과 날짜를 함께 밝힌 신뢰할 수 있는 출시 원문도 검토할 수 있습니다. 상품명·사진·구조는 공식 PDP에서 별도로 확인합니다. 미래 발매에는 공식 날짜 근거가 필요합니다.
- 수집 후보에 개수 상한은 없습니다. 네트워크 요청 전 명백한 제외 브랜드·품목, 모델 검토 미승인 상품, 날짜를 연결할 식별자가 없는 기록은 보류합니다. 같은 공식 URL은 한 번 읽고 각 품번을 별도로 검증합니다. Reader의 공통 요청 간격을 유지하며 25건마다 진행 수를 기록합니다.
- 제품 설명 원문은 사이트 미노출 검토용이며, 커밋된 수집 기록은 공개 저장소에서 열람할 수 있습니다. 사이트의 상품 설명은 짧은 분류·참고 이유로 구성합니다.

## 출처와 키워드

매거진·뉴스레터는 최근 30일의 개별 모델 원문에서 두 유형을 합쳐 독립 발행자 2곳 이상이 확인된 상품을 표시합니다. SNS는 최근 달력상 3개월에 확인한 아이템별 검색량·해시태그 게시물량을 구분합니다. 공식 상품·사진 증빙이 필요하며 미공개 수치를 0으로 채우거나 조회량으로 검색량을 대체하지 않습니다. 이커머스는 실제 순위·국가·카테고리·날짜가 확인된 페이지만 인정합니다.

매거진·공개 뉴스레터는 직접 RSS와 설정된 공개 원문을 읽고, 유효한 Jina Search가 있으면 추가 원문을 발견합니다. 접근 제한이나 날짜 누락 시 보류합니다. 이커머스 순위는 검색 순서를 이용하지 않습니다.

이번 주 스타일 키워드는 브랜드·모델·일반 신발명 단독을 제외하고 실제 검색어·복합 인기·해시태그 원순위를 플랫폼별 동일 가중치 `1 / 원순위`로 합산합니다. 같은 플랫폼의 동의어는 최고 순위 한 번만 기여하고, 원문 표기·원순위·종류·기간·국가를 보존합니다. 숫자 없는 공식 인기·매체 표현은 종합순위 없이 후단에, 미래예측은 별도 영역에 표시합니다. 실제 원순위가 없는 고정 주제를 인기순위로 채우지 않습니다.

키워드 클릭은 한영 동의어와 검토된 브랜드·모델 사전으로 유효한 출시 완료·발매 예정 상품 전체를 찾습니다. 복합어의 조건은 모두 맞아야 하며, 원문의 검색어 표기를 영어로 바꾸지 않습니다. 현재 인기의 168시간 유효기간, 보고서·미래 시즌 종료 정책, 매칭 기준은 `docs/keyword-ranking.md`를 확인하세요.

## 아카이브와 원본 보호

별도 엑셀은 만들지 않습니다. 기존 브랜드 위치를 먼저 확인하고, Ralph Lauren은 애슬레저, 기존 컨템포러리 목록의 나머지는 국내 브랜드 파일에 저장합니다. 저장 파일과 국가/브랜드 성격은 별도로 유지합니다. 모호한 분류는 사용자 검토 대상으로 남깁니다.

사용자가 승인한 유럽·글로벌 PUMA는 아웃도어·스포츠 파일에 저장하며 실제 시장 코드를 유지합니다. 중국 PUMA는 기존 중국 파일 분류와 읽기 전용 정책을 유지합니다.

아카이브 스크립트는 기존 셀을 덮어쓰거나 삭제하지 않고 검증된 새 행만 추가합니다. 설정과 운영 절차는 `docs/archive-integration.md` 등 `docs/archive*.md`를 확인하세요. 인증이 없으면 쓰기를 수행하지 않으며 대기열을 보존합니다. GitHub에 `GOOGLE_SERVICE_ACCOUNT_JSON` 또는 OAuth 자격 증명을 설정하고 해당 계정에 대상 기존 시트 편집 권한을 부여해야 합니다. 키 내용은 코드·로그·공개 파일에 저장하지 않습니다.

시트 쓰기 전에 원래 값·수식·서식·검증 규칙 등의 스냅샷과 처리 대기 영수증을 AES-256-GCM으로 암호화합니다. 별도 `archive-audit` 브랜치에 저장한 뒤 다시 읽어 일치 여부를 확인해야 실제 추가가 가능합니다. 필요한 `ARCHIVE_BACKUP_KEY`는 32바이트 Base64 GitHub Secret이며 GitHub 저장소 토큰은 실행 환경에서만 사용합니다. 백업 키는 교체 전에 기존 암호화 파일의 복구 가능성을 확인해야 합니다.

실행이 중단되어도 다음 실행이 원격 암호화 영수증을 먼저 읽습니다. 추가 여부가 불확실한 기록은 임의로 다시 추가하거나 원래 셀을 복원하지 않고 검토 대상으로 남깁니다. 시트 스냅샷·원본 메타데이터·처리 영수증을 평문 아티팩트나 공개 사이트에 게시하지 않습니다. 주간·일일·수동 실행은 같은 `shoes-publication` 동시 실행 제한을 사용합니다.

## 로컬 검증

```sh
npm ci
npx playwright install chromium
npm test
npm run test:ui
python -m unittest discover -s tests -p 'test_*.py'
npm run curate
npm run build
npm run archive
```

`npm run weekly`는 실제 전체 수집, `npm run keywords`는 상품·Signals·전체 수집시각을 보존하는 키워드만 갱신, `npm run daily`는 수집 없이 기한 점검, `npm run archive`는 기본 모의 실행입니다. 키워드 갱신은 Google Sheets를 호출하지 않습니다. Windows Edge를 사용할 때는 `PLAYWRIGHT_CHANNEL=msedge`를 설정할 수 있습니다.

UI 테스트는 Windows에서 설치된 Chrome을 기본 사용하며 `UI_BROWSER_CHANNEL=msedge`로 Edge를 지정할 수 있습니다. Linux CI는 설치된 Playwright Chromium을 사용합니다. 테스트용 상품은 별도 로컬 서버에서만 응답하고 공개 데이터에 기록하지 않습니다. 실제 Safari/iOS 검증은 별도로 필요합니다.

## 배포

Cloudflare 기존 Git 연동: production branch `main`, build `npm run build`, output `public`. `public/deployment.json`에서 배포 커밋을 확인합니다. 브라우저에 Jina/Google 인증 정보를 전달하지 않습니다.

스케줄·수동 게시 작업은 `main`에서만 실행됩니다. 작업 중 다른 커밋이 먼저 올라오면 게시 push를 중단합니다. 이미 검증한 작업에 다른 코드를 자동 병합해서 배포하지 않습니다. 수집 실패는 기존 공개본을 유지하며, 아카이브만 실패한 경우에도 검증된 신상품 공개본은 게시하고 실패 상태를 보고합니다. 이전 공개 진단 파일은 `collector/historical/`에 보존했습니다.

공식 API 참고: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule, https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/append
