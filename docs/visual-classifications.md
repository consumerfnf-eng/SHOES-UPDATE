# 사진 실루엣 보기

상품 목록의 **사진 실루엣** 필터와 데이터 분석의 **사진 실루엣 · 모델 수** 패널은 공개된 상품 사진의 형태를 살펴보는 별도 보기다. 공식 품목, 기능 카테고리, 상품 게시 자격, 기존 수동 검토, 저장함과 레퍼런스 보드를 변경하지 않는다.

## 공개 데이터 연결

`public/assets/app.mjs`는 첫 상품 표시 후 `public/assets/visual-classification.mjs`와 `public/data/visual-classifications.json`을 한 번만 비동기로 읽는다. 브라우저에서 모델 추론을 실행하지 않는다. 검증된 모델 그룹이 없거나 모듈·데이터를 사용할 수 없으면 실루엣 필터를 숨기고 비활성화하며 기존 상품 목록과 다른 분석은 유지한다. 분류 모델 수가 0인 실루엣 분석 패널도 숨긴다. 공개 화면에 미확인·근거 부족·로딩 실패 경고를 추가하지 않는다.

## 품질 기준에 따른 공개 보류

현재 재평가 표본은 87건이며 원본 55.2%, 업데이트 모델 70.1%다. 모델은 `validated: false`이고 95% 기준을 충족하는 공개 클래스가 없으므로 정적 공개 스냅샷은 `records: []`로 배포한다. 이는 의도된 품질 제한이며 테스트 실패나 상품 데이터 누락으로 취급하지 않는다. 보조 학습용 정답을 수동 승인 기록으로 바꿔 공개하지 않는다.

이 상태에서는 이전 또는 강제된 실루엣 선택이 있어도 상품을 걸러내지 않으며 공식 품목과 기존 분석은 그대로 유지한다. 전체 prepared 상품의 기존 디자인 그룹 등록은 계속 수행한다. 이후 실제 소유자가 승인한 사진 결과가 보호된 검토 overlay로 도착하면 revision을 갱신하고, 실제 분류 가능한 모델 그룹이 생긴 경우에만 필터와 해당 범위의 패널을 표시한다. 제외 결정만 있거나 현재 상품과 연결되지 않는 기록은 컨트롤을 활성화하지 않는다.

스냅샷 등록은 핵심 모듈의 `useVisualClassifications(snapshot)`에 위임한다. 모델 기록은 검증된 모델과 카테고리별 신뢰도·마진 기준을 통과해야 하며, 수동 승인 기록은 모듈의 수동 승인 규칙을 따른다. 불확실한 후보를 공개 UI가 추정하거나 이름·URL·기존 품목에서 보충하지 않는다. 직접 결과는 실제 `presentation.cachedPath`의 사진 SHA와 연결하며, 별도 사진 결과가 없는 색상은 아래의 기존 디자인 그룹 규칙 안에서만 대표 결과를 공유한다.

## 디자인 모델 대표 이미지

원사진 12,534장과 기존 디자인 모델 4,264개를 구분한다. 추론 대상은 별도 모델 manifest가 선택하는 디자인별 안정된 대표 이미지 한 장이며, 모든 색상 사진을 각각 추론한 것으로 표시하지 않는다. 이 수치는 작업 시점의 리소스 규모 설명이며 UI 집계에 상수로 넣지 않는다.

UI는 성별·출처 필터로 좁히기 전의 전체 prepared 상품을 `useVisualModelProducts(products, {keyOf: p => p.brand + '|' + variantGroupKey(p)})`로 등록한다. prepared 상품 배열 또는 실루엣 revision이 변경되면 다시 등록한다. 기존 사이트 디자인 키만 사용하며 이름으로 새로운 그룹을 만들지 않는다. 승인 SHA의 합의 결과는 같은 기존 디자인 그룹 안의 다른 색상·성별 하위 보기에도 적용된다.

`visualClassification(product)`가 `basis: 'model-design'`으로 반환한 색상에는 **동일 모델의 확인된 대표 이미지 기준** 툴팁 배지를 표시한다. 직접 SHA 결과에는 이 배지를 붙이지 않는다. 정확한 사진 SHA에 대한 소유자 제외는 대표 이미지 결과로 덮어쓰지 않으며, 서로 다른 직접 승인 카테고리가 있는 디자인에는 fallback이나 다수결 카테고리를 만들지 않는다.

공개 coverage와 그래프는 실제 분류된 디자인 모델 수를 기준으로 한다. 대표 이미지 한 장의 승인 결과를 공유하는 여러 색상을 개별 추론 완료 건수로 부풀리지 않는다.

필터 선택지는 핵심 모듈의 `VISUAL_CATEGORIES`에서 가져온다: `low-profile`, `chunky`, `retro-tech-runner`, `ballet-mary-jane`, `mule-slipper`, `court-other`, `boot`, `sandal`, `performance`.

정적 스냅샷 등록 후 기존 팀 Basic 인증을 사용하는 `GET /api/visual-classifications`를 같은 출처 자격 증명과 `no-store`로 한 번 조회한다. 응답은 `useVisualClassificationReviews({schemaVersion:1,records:[{imageHash,category,status:'approved'|'excluded'}],updatedAt})`에 그대로 위임한다. 승인·제외 반영 후 실루엣 및 카테고리 revision을 올려 목록과 분석을 다시 그린다. 직원이 페이지를 새로 열거나 새로고침하면 최신 소유자 검토를 반영한다.

이 호출은 조회 전용이다. 공개 UI는 검토를 생성하거나 후보를 자동 승인하지 않으며 확률·임베딩·비공개 큐를 요청하거나 표시하지 않는다. 검토 쓰기와 권한 검사는 별도 보호된 관리자 API가 맡는다. 로컬 404, 서비스 503, 인증 실패, 유효하지 않은 검토 응답은 정적 분류를 유지하며 조용히 무시한다.

## 필터와 집계

- 기존 출처·브랜드·LUX/SPORTS/CASUAL 그룹·검색·품목 필터를 적용한 결과에 실루엣 필터를 추가한다.
- 실루엣 필터는 `브랜드 + variantGroupKey`별 승인 결과가 하나의 카테고리로 일치하는 모델을 선택한다. 선택한 모델의 허용된 모든 색상을 유지하며 사진이 미분류인 색상도 제거하지 않는다. 기존 게시·출처·성별 정책을 통과한 사진만 합의 판정에 사용한다.
- 분석은 같은 필터 범위를 사용한다. `visualModelDistribution(rows, {keyOf: p => p.brand + '|' + variantGroupKey(p)})`로 브랜드별 모델을 구분하고 색상·SKU 중복을 제거한다.
- 서로 다른 승인 실루엣이 있는 같은 모델은 분포에서 제외하고 별도 건수를 알린다. 검색이나 색상 조건이 좁아져도 같은 모델의 다른 허용 사진을 함께 확인한다. 상충 모델에는 다수결 카테고리를 부여하지 않고 특정 실루엣 필터에서도 제외한다. 승인 결과가 없는 모델은 미분류 건수로 표시하며 후보 라벨은 노출하지 않는다.
- 그래프 숫자는 현재 게시된 조사 대상의 **모델 수**다. 백분율은 분류된 모델 안의 구성비이며 시장 점유율이 아니다. 실제 MLB 상품 표본이 없는 상태에서 MLB 실루엣 비교를 만들지 않는다.

스냅샷이 늦게 도착하면 실루엣 revision을 올려 목록 및 분석 캐시를 갱신한다. 필터 초기화와 해제 칩은 실루엣 선택도 초기화한다. 다른 상품 속성이나 저장된 보드에는 분류를 덮어쓰지 않는다.

## 확인 방법

기본 회귀 테스트:

```sh
node --test tests/visual-classification-ui.test.mjs
```

Playwright가 설치된 환경에서 실제 브라우저 상호작용까지 확인:

```powershell
$env:VISUAL_UI_BROWSER = '1'
node --test tests/visual-classification-ui.test.mjs
```

브라우저 테스트는 로컬 fixture 서버와 별도 브라우저 컨텍스트를 사용한다. 실제 카탈로그나 저장된 사용자 보드를 수정하지 않는다. 늦은 데이터 로딩, 필터·그룹 전환, 모델 집계, 색상별 불일치, 초기화, 모바일 가독성, 실패 시 기본 목록 유지를 확인한다.

## 오프라인 운영과 추가 학습

기존 사용자 모델과 원본 학습 자료는 `.secrets/clip-models/user-v4/`에 복사 보존한다. 새 분류기와 평가 기록도 `.secrets/clip-models/`, `.secrets/clip/`에만 저장한다. 모델 가중치·임베딩·검수 후보·학습 자료를 공개 저장소나 일반 사이트에 올리지 않는다. 선택적 Python 환경은 `requirements-clip.txt`이며 기존 모델의 scikit-learn 버전과 이미지 전처리를 유지한다.

`clip_encoder.py`는 기존 로컬 DFN2B 체크포인트의 이미지 인코더만 mmap/meta/assign으로 읽는다. 원래 특징과의 수치 일치를 확인한 메모리 절약 로더다. `clip_classify.py`는 낮은 프로세스 우선순위·최대 4개 CPU 스레드, 작은 배치, 이미지 SHA·전처리 버전별 SQLite 캐시를 사용한다. 사진 처리 중단 후에도 완료된 특징은 재사용하며 빈 사진을 흰색 학습 예제로 대체하지 않는다.

```powershell
# 현재 모델: 검증 기준 미달이므로 400건 검수용 표본만 갱신.
# validated 모델이 준비된 경우에만 전체 디자인 대표 사진 처리로 전환.
node scripts/update-visual-classifications.mjs --background --publish --sync-admin

# 관리자 확정 라벨을 비공개 파일로 내보내기
node scripts/export-visual-owner-labels.mjs
```

작업 상태는 `logs/clip-background-update.log`, 중복 작업 잠금은 `.secrets/clip/update.lock`에 기록한다. 잠금의 프로세스가 살아 있으면 추가 작업을 실행하지 않는다. 모델·완료된 검증 파일이 없거나 추론이 미완료이면 기존 공개 스냅샷을 유지한다. 미검증 모델로 전체 카탈로그를 반복 처리하지 않는다.

학습·재현용 스크립트는 `clip_train.py`(기존 사용자 특징+새 학습 표본), `clip_refine.py`(신발 전체를 보존하는 입력의 분류기 선택), `clip_validate_frozen.py`(학습·기준 선택 없이 별도 새 표본으로 평가)다. 최초 300개 중 학습·조정·시험은 브랜드로 분리했고, 첫 시험 결과를 확인한 뒤에는 서로 다른 사진·모델의 새 100개를 별도로 확보했다. 100개 중 판독 가능한 87개로 최종 비교하고, 모호한 13개는 강제로 정답 처리하지 않았다.

사진 기준 라벨은 독립적인 **assistant 사진 검수**이며 소유자나 전문가가 확정한 인간 정답으로 표현하지 않는다. 이 보조 라벨을 공개 수동 승인으로 바꾸지 않는다. 공개 수동 승인은 기존 소유자 인증·CSRF·사진 SHA·revision 검사를 통과한 관리자 결정만 사용한다. 예측값을 새 학습 정답으로 재사용하지 않는다.

다음 학습에는 관리자가 확정한 라벨의 정의와 이미지 적합성을 먼저 확인한다. 이미 성능을 확인한 시험 표본을 반복해서 임계값 조정에 사용하지 말고 새 시험 표본을 분리해야 한다. 카테고리별 조정/시험 표본 최소 8개와 관측 정밀도 95%를 모두 충족한 범주만 자동 공개한다. 표본 수와 관측값을 함께 기록하며 이를 전체 사이트 정확도의 보장으로 표현하지 않는다.
