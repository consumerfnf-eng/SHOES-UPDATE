# 우선 사진 96개 검수

관리자 대시보드의 **우선 사진 96개 검수** 버튼으로 사진 실루엣 검수 패널을 연다. 기본 범위는 `batch=priority`, 기본 검수 상태는 **검수 필요 · 미완료**다. **전체 후보**는 기존 전체 후보 목록을 별도로 보여주며 우선 배치 학습 요청은 표시하지 않는다.

1. 사진을 보고 분류를 직접 선택한다. 사진을 누르면 모달에서 확대할 수 있다.
2. **승인 · 저장하고 다음** 또는 **제외 · 저장하고 다음**을 누른다. 제외는 분류 선택 없이 가능하다.
3. 기본 보기에서는 저장한 사진이 사라지고 다음 미완료 사진으로 이동한다. 진행률과 남은 수는 서버 응답을 다시 읽어 갱신한다.
4. 전체 96개에 대한 승인·제외 저장이 끝나 `remaining: 0`이 확인되면 **검수 완료 · 추가 학습 요청**을 누를 수 있다.

미검수 사진은 모델 제안을 포함하더라도 분류를 미리 선택하지 않는다. `blindReview: true` 또는 `reviewRole: test`인 사진에는 **분류 기준 확인용 사진**이라는 중립 설명만 표시하고 모델 제안·점수·다른 후보·제안 이유를 숨긴다. 이미 저장된 소유자 승인 분류는 재검토 시 선택값으로 유지한다. 명시적으로 학습용·기준 조정용으로 표시된 일반 후보의 모델 제안은 결정 버튼 아래의 접힌 참고 영역에서만 볼 수 있다. 전체 후보 응답에서 역할 정보가 빠진 사진도 제안과 이유를 숨겨 블라인드 답안 힌트가 섞이지 않도록 한다.

## 분류 기준

- **퍼포먼스 · 축구/육상**은 축구화의 스터드·육상화의 스파이크 등 전용 경기 구조다. 일반 러닝화는 이 항목이 아니라 **레트로 테크 러너**에서 검토한다.
- **레트로 테크 러너**에는 복고 러너와 현대적인 메시 러닝화의 형태가 포함된다. 실제 운동 성능을 판정하는 기능 분류가 아니다.
- **부츠**는 부츠 특유의 몸통·발목 구조로 판단하며 농구화나 캔버스 하이탑과 구분한다.
- **뮬·슬리퍼**는 뒤꿈치가 열린 형태다. 뒤꿈치가 닫힌 슬립온을 끈이 없다는 이유만으로 포함하지 않는다.

전체 9개 분류의 설명은 화면의 **분류 기준 보기**에서 확인한다. 판단하기 어렵거나 사진이 부적절하면 임의로 추측하지 않고 제외한다.

## API와 작업 상태

- 목록: `GET /api/admin/visual-classifications?batch=priority&page=1&status=review-needed`.
- 전체 후보: 같은 목록 API에서 `batch`를 생략한다.
- 저장: 기존 `POST /api/admin/visual-classifications/review`에 `imageHash`, 직접 고른 `category` 또는 제외 시 `null`, `status`, `expectedModelVersion`, `expectedRevision`을 전달한다. 기존 소유자 세션·CSRF 및 동시 수정 검사는 유지한다.
- 학습 요청: `POST /api/admin/visual-classifications/train`에 `{batchId: 'priority-20261106-v1'}` 등 실제 응답의 배치 ID를 보낸다.

진행 카운터는 `batch.total/reviewed/approved/excluded/remaining`을 사용한다. 숫자가 없거나 합계가 일치하지 않으면 학습 요청을 활성화하지 않는다. 브랜드 필터로 목록이 비어도 배치 전체의 남은 수로 판단한다.

`queued`, `running`, `completed`, `held`, `failed`를 백엔드 상태 그대로 구분한다. 대기·실행 중에는 목록을 다시 만들지 않는 상태 조회로 갱신한다. completed/held는 중복 요청을 잠그고 failed만 재요청할 수 있다. 응답의 안전한 `result.message`, `releasedCategories`, 검수 분할·평가 건수만 설명하며 작업 완료를 배포 완료로 단정하지 않는다.

**이 PC가 켜져 있고 네트워크에 연결되면 백그라운드 처리. 기준 통과 범주만 자동 반영.** 예약 작업은 약 5분 간격으로 요청을 확인하며, 추가 학습 완료와 공개 검증·반영은 별도 단계다. 이 UI는 학습을 직접 실행하거나 백엔드가 반환하기 전에 완료 상태를 만들지 않는다.
